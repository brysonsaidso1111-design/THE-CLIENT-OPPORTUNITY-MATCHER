## Shared rules for every stage

1. Read the entire authoritative stage specification and its existing issue before editing code.
2. Consume upstream contracts; do not duplicate or redefine them. Record contract/policy version where reproducibility requires it.
3. Keep source/provenance, eligibility, semantic fit, score, rank, intelligence, quality/risk/recommendation, user intent, lifecycle, and technical execution distinct.
4. Use deterministic tests first; label mocks separately from live integration tests.
5. Include success, valid empty, partial, unknown, invalid, denied, failed, timeout, retry, concurrency, and recovery behavior where relevant.
6. Update the existing issue with artifact links, commit/PR, test command/result, unresolved defects, and explicit outgoing handoff.
7. Mark VERIFIED only with actual passing evidence on a named commit.
8. A stage implementation PR must not silently modify another stage's contract. Cross-stage changes require explicit, narrowly scoped contract reconciliation and updates to all affected existing handoff issues.
